MINDEX CODE CHALLENGE - PROJECT OVERVIEW AND AI USAGE SUMMARY

PURPOSE
This file gives a concise overview of the starter project and explains how I used AI during the challenge. Detailed AI interactions are separated into Task 1 and Task 2 logs.

======================================================================
1. CHALLENGE OVERVIEW
======================================================================

The provided application is a Java 17 Spring Boot REST API backed by an in-memory MongoDB-compatible database. Employee data is loaded from a serialized snapshot when the application starts. The starter application already supports creating, reading, and updating employees.

Existing endpoints:

POST /employee
GET  /employee/{id}
PUT  /employee/{id}

The challenge adds two features:

Task 1 - Reporting Structure
Create a ReportingStructure containing an employee and numberOfReports. The total must include direct and indirect reports and be calculated on demand rather than persisted.

Task 2 - Compensation
Create persistent Compensation data associated with an Employee. Compensation must include at least salary and effectiveDate and must support create and read REST operations through the persistence layer.

======================================================================
2. STARTER ARCHITECTURE
======================================================================

HTTP Request
    -> Controller
    -> Service Interface
    -> Service Implementation
    -> Repository / DAO
    -> In-Memory MongoDB

Controller
Handles HTTP routing and request/response boundaries.

Service Interface
Defines the operations exposed by the application layer.

Service Implementation
Contains business logic, validation, calculations, and repository coordination.

Repository / DAO
Handles persistence and retrieval through Spring Data MongoDB.

Data Classes
Represent the application's domain and response objects.

Startup flow:

employee_database.json
    -> DataBootstrap
    -> EmployeeRepository
    -> In-Memory MongoDB

======================================================================
4. HOW I USED AI
======================================================================

I used AI as a design-review, implementation-support, troubleshooting, and validation tool. I tried to establish an approach first, then used AI to challenge assumptions and identify edge cases rather than treating the first generated solution as automatically correct.

The main areas where I used AI were:

- Reviewing whether my design fit the starter architecture.
- Comparing implementation choices and their tradeoffs.
- Identifying security and data-validation concerns.
- Reviewing recursion, persistence, and data-modeling decisions.
- Suggesting edge cases for automated testing.
- Explaining framework behavior when I encountered Spring/Gradle issues.
- Reviewing production concerns that were outside the scope of the challenge.

I independently ran the application and tests and recorded only results I actually verified. Recommendations that were not implemented are identified as production considerations rather than completed work.

Detailed interactions are documented separately in:

- ai_log_task_2_compensation.txt
