MINDEX CODE CHALLENGE - PROJECT OVERVIEW

============================================================
1. ORIGINAL PROJECT PROMPT
============================================================

A Spring Boot web application is provided with employee data. When the
application starts, an in-memory Mongo database is loaded from a saved
snapshot. Data can be read and changed while the application is running
without changing the original snapshot.

The application runs with:

gradlew bootRun

The project targets Java 17.

Existing Employee endpoints:

POST /employee
GET  /employee/{id}
PUT  /employee/{id}

The ID used by these endpoints is the employeeId field.

Task 1:
Create a ReportingStructure type containing an employee and the total
number of direct and indirect reports under that employee. Add a REST
endpoint that calculates and returns the ReportingStructure for an
employeeId. The calculated result should not be persisted.

Task 2:
Create a Compensation type containing at least salary and effectiveDate.
Associate each Compensation with an Employee. Add REST endpoints to
create and read Compensation using the persistence layer.

Delivery:
Upload the completed project to a publicly accessible Git repository.

============================================================
2. PROJECT PURPOSE
============================================================

This project is a Spring Boot REST API for managing employee information.
The starter application already supports creating, reading, and updating
employees. The coding challenge extends the system with:

1. A calculated employee reporting structure.
2. Persistent employee compensation information.

============================================================
5. SYSTEM ARCHITECTURE
============================================================

The application uses a layered architecture:

HTTP Request
    |
    v
Controller
    |
    v
Service Interface
    |
    v
Service Implementation
    |
    v
Repository / DAO
    |
    v
In-Memory MongoDB

Controller:
Receives HTTP requests, reads request data, calls a service, and returns
JSON responses.

Service Interface:
Defines the operations available to the controller.

Service Implementation:
Contains the business logic, validation, calculations, and repository
calls.

Repository / DAO:
Reads and writes data in MongoDB.

Data Classes:
Define the objects used by the application, such as Employee,
ReportingStructure, and Compensation.

============================================================
6. STARTUP DATA FLOW
============================================================

employee_database.json
    |
    v
DataBootstrap
    |
    v
EmployeeRepository
    |
    v
In-Memory MongoDB

DataBootstrap reads employee_database.json when the application starts
and inserts the employee records into the in-memory database. Restarting
the application resets the database to the original snapshot.

7. PROVIDED EMPLOYEE HIERARCHY
============================================================

John Lennon
|-- Paul McCartney
`-- Ringo Starr
    |-- Pete Best
    `-- George Harrison

John has four total reports:

- Paul and Ringo are direct reports.
- Pete and George are indirect reports through Ringo.

The directReports entries may contain only an employeeId. The complete
Employee record must therefore be retrieved from EmployeeRepository when
following the reporting hierarchy.
